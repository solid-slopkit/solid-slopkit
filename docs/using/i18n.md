# Using slopkit i18n in an app

This guide is for coding agents that add `@solid-slopkit/i18n` to a SolidJS 2.x app. It covers how to install it from npm, how to wire it up, and how to make the docs shipped in the package available to future agent sessions.

Repository: https://github.com/solid-slopkit/solid-slopkit (the package is in `packages/i18n`)

Docs site: https://solid-slopkit.github.io/solid-slopkit/i18n/. It is built from `main` and can be ahead of the latest release; the docs inside the installed package match the installed version, so prefer those.

## The package

`@solid-slopkit/i18n` keeps translations next to the components that use them: each `*.i18n.jsonc` file holds every locale, and a Vite plugin compiles it into a module whose import gives the typed messages of the active locale. It depends on no other `@solid-slopkit` package. With `@solid-slopkit/components`, messages fill the components' text props and the active locale goes to its provider.

It needs `solid-js` and `@solidjs/web` 2.x, which a Solid 2 app already has, and Vite for the plugin. It ships uncompiled JSX under the `solid` export condition, so the app compiles it with its own Solid plugin (`@solidjs/vite-plugin`). This needs no configuration.

## 1. Install

```bash
pnpm add @solid-slopkit/i18n
```

## 2. Set it up

The package has an index for agents at `node_modules/@solid-slopkit/i18n/dist/source/llms.md`, with links to a guide per topic. Read it. The steps below are only the wiring that has to happen once.

Add the plugin before the Solid plugin in `vite.config.ts`:

```ts
import { slopkitI18n } from '@solid-slopkit/i18n/vite';

export default defineConfig({
  plugins: [slopkitI18n({ locales: ['en', 'de'], defaultLocale: 'en' }), solid(/* … */)],
});
```

Let TypeScript find the generated types, in `tsconfig.json`:

```jsonc
{
  "compilerOptions": {
    "allowArbitraryExtensions": true,
    "rootDirs": ["src", "node_modules/.slopkit-i18n/types/src"],
  },
}
```

**Editors.** The generated types are in `node_modules`, and some editors don't watch it, so the TypeScript server misses new and changed types: the import of a new translation file stays unresolved, and types go stale. In Zed, scan the folder (project `.zed/settings.json` or user settings), then reload the window once. The list replaces Zed's default (`[".env*"]`), so keep `.env*`:

```jsonc
// Generated i18n types live in node_modules (gitignored). Scan them so the
// TypeScript server sees new and changed files without a restart.
"file_scan_inclusions": [".env*", "**/node_modules/.slopkit-i18n/**"],
```

VS Code watches `node_modules` by default. In any editor that still misses them, restart the TypeScript language server.

Wrap the app in the provider. With `@solid-slopkit/components`, put it inside `SlopkitUi` and pass the locale to `SlopkitUi` for date and number formatting; see `guides/slopkit-components.md` in the package.

```tsx
import { I18nProvider } from '@solid-slopkit/i18n';

<I18nProvider initialLocale="en">{/* the app */}</I18nProvider>;
```

If the project runs `tsc` in CI or a `typecheck` script, run `slopkit-i18n typegen` before it.

## 3. Make the package docs available to later sessions

The package ships a skill (a task guide, `skills/<area>/SKILL.md`) and LLM references (the `llms.md` index and the guides it links). Both always match the installed version. Tell future agents about them in the app's agent instructions: add this section to `AGENTS.md`. Create the file if the app has none. If the file has a generated block (the templates' `<!-- BEGIN solid-2.0-primer -->` … `<!-- END solid-2.0-primer -->`), add the section after it, never inside it.

```markdown
## slopkit i18n

This app uses `@solid-slopkit/i18n`, installed from npm. To upgrade, run `pnpm up @solid-slopkit/i18n --latest`.

Read the docs inside the installed package, not the web; they match the installed version:

- `node_modules/@solid-slopkit/i18n/dist/source/llms.md`: setup and a guide per topic (translation files, messages, locale, loading and SSR). Skill: `node_modules/@solid-slopkit/i18n/skills/i18n/SKILL.md`.

Before adding or changing translations, read the skill first, then the guide for each topic you use.
```

**Claude Code** reads `CLAUDE.md`, not `AGENTS.md`. If the app has no `CLAUDE.md`, create one that contains the line `@AGENTS.md`. To make the skills load on their own when a task matches them, also link each one into `.claude/skills`:

```bash
mkdir -p .claude/skills
for skill in node_modules/@solid-slopkit/*/skills/*/; do
  ln -sfn "../../$skill" ".claude/skills/$(sed -n 's/^name: //p' "$skill/SKILL.md")"
done
```

Commit the links. They are relative and point into `node_modules`, so they resolve after `pnpm install` on any clone and follow upgrades. Run the loop again after an upgrade, to pick up new skills.

## 4. Check it works

1. `pnpm build` succeeds, and `pnpm exec slopkit-i18n typegen && pnpm exec tsc --noEmit` reports no errors.
2. `pnpm dev`, open the app, switch the locale, and check that the text changes and the browser console shows no errors.
